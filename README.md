# Winter War: Summa (prototype)

First-person shooter prototype set in the Winter War 1939–40, Battle of Summa.
Godot 4.7, GDScript, Compatibility renderer (so it can be exported to the web).

## Controls
| Action | Key |
|---|---|
| Move | W A S D |
| Look | Mouse |
| Sprint | Shift (uses stamina) |
| Crouch | C (or Ctrl – but avoid Ctrl in the browser, Ctrl+W closes the tab) |
| Jump | Space |
| Fire / aim down sights | Left mouse / right mouse (on the Maxim: look through its sights) |
| Reload | R |
| Mosin-Nagant / Suomi | 1 / 2 |
| Use / leave the Maxim (in the bunker), take from an ammo crate | F |
| Bandage (heals 50, 2 per life) | B |
| Pause menu | Esc |
| Debug: god mode / enemy state labels / debug text | F1 / F2 / F3 |

## Running
- **F5** starts from the main menu. To jump straight into a match while testing, open
  `scenes/game.tscn` and press **F6** (Run Current Scene).

## Web version (browser)
1. **Once:** in Godot choose **Editor → Manage Export Templates → Download and Install** (~1 GB).
2. **Quick test from the editor:** the small browser/HTML5 icon button at the top right of the
   editor ("Run in Browser") exports and opens the game. It is greyed out when the export
   templates are missing or the Web preset has a problem – **Project → Export… → Web** then shows
   the reason in red at the bottom.
3. **Export files:** **Project → Export… → Web → Export Project** → saves to `export/web/`.
   Opening `index.html` by double-clicking does **not** work (browsers block it from disk).
   Instead double-click **`export/web/play_in_browser.bat`**: it starts a small local web server
   (PowerShell, nothing to install) and opens the game. Close its window to stop it.
   (If the .bat is missing, copy `serve.ps1` and `play_in_browser.bat` from `tools/web/`.)
4. **Share on itch.io (free):** create a new project, *Kind of project* = **HTML**. Zip the
   *contents* of `export/web/` (so `index.html` is at the top of the zip), upload it and tick
   **"This file will be played in the browser"**. Viewport 1280 × 720, enable the fullscreen
   button. "SharedArrayBuffer support" is not needed. Keep it as **Draft** (or *Restricted*)
   while testing – only you (and people you give the link/password to) can play it.

## Settings and benchmark
- **Settings** (main menu or Esc menu): graphics quality Low / Medium / High, mouse sensitivity,
  volume, fullscreen. Saved automatically. Browsers start on Medium, desktop on High.
- **Benchmark** (main menu): a fixed 60-second run with a 16-soldier attack. The result screen
  shows FPS, slowest frames, draw calls, triangles, physics time and memory. On desktop it
  turns V-Sync off during the test, so the FPS shows the real speed (not just your monitor's
  60 Hz); browsers always stay in sync with the screen.
  **Copy results** puts the text on the clipboard.

## Performance budget (measured after P1 graphics, High quality)
| | Now | Budget for future graphics |
|---|---|---|
| Draw calls per frame | ~165 average, ~220 max | ≤ 300 |
| Triangles per frame (incl. shadows) | ~275 000 | ≤ 400 000 |
| CPU: physics (16 enemies) | ~2.5–3 ms (desktop) | ≤ 8 ms total in the browser |
| Download | ~52 MB (≈17 MB compressed) | ≤ 60 MB |
| Textures | 6 generated textures, ≤ 2048 px, VRAM-compressed | ≤ 2048 px, VRAM-compressed |

## Graphics (P1: clear freezing day)
- **Sky**: `resources/shaders/winter_sky.gdshader` (blue gradient, glow around the low sun,
  thin clouds). Its colours can be changed in `resources/materials/winter_sky.tres`.
- **Snow**: `resources/shaders/snow.gdshader` – wind ripples, soft patches, sparkles, ice on
  the bog and trampled snow on the trench floor. Material: `resources/materials/snow_ground.tres`.
- **Log walls**: `resources/shaders/log_wall.gdshader` – trench walls and bunker, snow on top.
- **Trees**: `resources/shaders/spruce.gdshader` + `scripts/world/forest_scatter.gd` (two spruce
  shapes close up, a simple one further away – each tree softly dissolves into the other –
  and a ring of distant forest on the horizon).
- **Textures** in `assets/textures/` are generated by `tools/make_textures.py` (Python), so no
  outside assets are needed. Real photo textures can replace them later (same file names).
- Sun direction/colour and the haze are on the **Sun** and **WorldEnvironment** nodes in
  `levels/test_level.tscn`.

## Weapons (W1)
- **Mosin-Nagant** and **Suomi** use real 3D models (CC-BY, see `CREDITS.md`). The downloads
  in `assets_source/` are unpacked and their textures shrunk by `tools/import_weapons.py` into
  `assets/models/weapons/`.
- **Maxim M/09-21** stands in the bunker at the firing slit (`scenes/weapons/maxim_mg.tscn`,
  script `scripts/weapons/mounted_gun.gd`, data `resources/weapons/maxim_m09_21.tres`).
  Walk up to it and press **F**; **R** loads a new belt (250 rounds, unlimited belts);
  **F** again to leave. It turns 14° left / 40° right and a little up and down – as far as
  the slit allows.
- The models' licence (CC-BY 4.0) requires naming their makers: `CREDITS.md` and the
  **Credits** button in the main menu. Keep them when you publish the game.

## Arms and Maxim polish (W2)
- **Your own arms** (`scripts/player/fp_arms.gd`, node `Player/Head/Camera3D/Arms`): white
  snow-camo smock sleeves (lumipuku) over the grey tunic and white wool trigger-finger mittens,
  built in code as one mesh with a skeleton (one draw call). The hands are placed on the
  gun's grip points every frame – `GripR` / `GripL` markers on each view model and on the
  Maxim – and the elbows bend to fit ("two-bone IK"). The right hand works the Mosin's bolt
  (`BoltGrip`, moves with the bolt); one hand goes to the pouch when reloading.
  To move a hand, move the marker (in `tools/build_scenes.gd`, `_grip()`); the shoulders and
  elbow direction are exported values on the Arms node.
- **Aiming closer**: the sights now come nearer the eye (Mosin 0.39 m, Suomi 0.35 m; were
  0.42 / 0.40). Change `ads_eye_distance` on a view model to tune it.
- **Maxim**:
  - right mouse brings your eye down behind the rear sight (`Pivot/SightEye`);
  - the model's own belt-feed animation plays while firing (cartridges move in, empty cases drop);
  - the water jacket heats up: about 120 rounds of non-stop fire make it **steam** (and hiss),
    about 390 boil it – **OVERHEATED**, no firing until it cools to about half (~8 s);
  - short bursts never overheat it (a hot gun cools faster);
  - the HUD shows a heat bar while you are on the gun;
  - the heat numbers are in `maxim_m09_21.tres` (Heat group): `heat_per_shot`, `cooling_rate`, …;
  - the right hand feeds the new belt when you press R.

## The battle (G1)
- **Goal:** hold the line until dusk – clear all waves (Easy 6 / Normal 8 / Hard 10) and you win.
- **Losing:** if too many Soviets are inside your trench at the same time (Easy 6 / Normal 4 /
  Hard 3), the line is broken. The HUD warns "SOVIETS IN THE TRENCH: x / y".
- **The assault:** soldiers advance to a jump-off point in front of the trench, fire from there
  for a while, then rush, jump into the trench and fight inside it.
- **Supplies:** two ammo crates (a niche in the trench next to the first spawn point, and the
  bunker): **F** refills spare ammo and bandages. **B** = bandage (+50 health, 3 s, no shooting).
  Everyone is patched up to full health when a wave is cleared.
- **Dusk:** after every cleared wave the sun sinks and the light turns to evening.
- **End screen:** victory / defeat with waves held, kills, deaths, hit percentage, time;
  Play again or Main menu.
- **Difficulty:** chosen in the main menu (saved). The numbers are in
  `resources/difficulty/easy.tres`, `normal.tres`, `hard.tres` – open them in the Inspector.
- Scripts: `scripts/game/match_director.gd` (rules), `scripts/game/dusk.gd`,
  `scripts/world/ammo_crate.gd`, `scripts/ui/end_screen.gd`; the enemy's new ASSAULT state is in
  `scripts/enemies/enemy.gd`.

## Effects, sound and soldiers (P2)
- **Soviet soldiers** are built in code (`scripts/enemies/soldier_mesh.gd`): greatcoat, budenovka,
  boots, Mosin with bayonet – one mesh with a skeleton, so each soldier is a single draw call.
  `scripts/enemies/soldier_visual.gd` animates them in code: walking/running, kneeling to
  fire, rifle carried / held forward / shouldered, recoil, flinching when hit, falling.
- **Effects** (`scripts/weapons/impact_effects.gd`): snow sprays, wood splinters, cloth dust,
  gun smoke (your own gun's is fainter), breath vapour, drifting snow (High/Medium).
- **Sound**: audio buses in `default_bus_layout.tres` (SFX with an outdoor echo, Ambience,
  UI), wind and the distant battle (`scripts/game/ambience.gd`, muffled down in the trench),
  the crack of bullets passing close, a red arc showing where a hit came from. These sounds are
  made by `tools/make_sounds.py` – they can be swapped for real recordings later (same names).
- **Footsteps** use real recordings only: put .ogg/.wav files with "snow", "trench" or "wood" in
  the name into `assets/audio/footsteps/` (see the README there – e.g. Kenney "Impact Sounds",
  CC0). Without files the game has no footsteps. (The generated ones sounded bad.)
- **Settings**: a separate "Wind and battle" volume, and "Breath vapour" on/off.
- **Reload and "you got hit" sounds** use real recordings only (the generated ones sounded bad):
  put files named `reload_mosin…`, `reload_suomi…`, `reload_maxim…` and `hurt…` (several
  hurt files = a random one each time) into `assets/audio/recorded/` – see the README there.
  Without files these moments are silent.

## Editing the trench and bunker
They are built from CSG shapes in `levels/source/trench_csg.tscn` and baked into plain meshes
(`levels/baked/`) because CSG is slow to load in a browser. After editing the CSG scene, the
meshes and the navigation mesh must be re-baked (`tools/bake_csg.gd`, then `tools/bake_nav.gd`
– or ask Claude to do it).

## Folders
- `autoload/` – scripts that are always loaded (NetworkManager)
- `scenes/` – game.tscn (a match), player.tscn
- `levels/` – test_level.tscn (terrain, forest, trench, bunker)
- `scripts/` – all game code, grouped by topic
- `resources/` – materials, weapon data (`resources/weapons/*.tres`) and enemy data
  (`resources/enemies/*.tres`) – tune weapons and enemies here
- `ui/` – main menu, HUD, pause menu, theme (`ui/winter_theme.tres`)
- `assets/` – sounds (placeholders), generated textures (`assets/textures/`), weapon models
  (`assets/models/weapons/`)
- `resources/shaders/` – sky, snow, log wall, spruce and tree-line shaders

## Multiplayer-ready design
- Single player = host with no clients (OfflineMultiplayerPeer, our peer id is 1).
- Player nodes are named after their peer id. `PlayerInput` reads the keyboard/mouse;
  `Player` only reads `PlayerInput`, and only the host moves players.
- `MultiplayerSpawner` creates players; `MultiplayerSynchronizer` nodes sync input and state.
- Shooting: the owner's WeaponController decides when the trigger fires and plays effects,
  then calls `server_fire` on the host, which checks ammo/fire rate, raycasts and applies
  damage through `take_damage()`.

## Enemy navigation
Enemies walk on a pre-baked navigation mesh (`levels/test_level_navmesh.res`).
If you change the level (terrain, trench, trees), open `levels/test_level.tscn`,
select the **Navigation** node and click **Bake NavigationMesh** in the toolbar.
